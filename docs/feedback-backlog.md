# noiseless フィードバック backlog

- 作成日: 2026-06-02
- 目的: 使ってみて気づいた要望を、重複なく・漏れなく（MECE）整理して、すぐ参照できるようにする
- 分類軸: **対応の種類**（質問 / 方針 / 実装）。1要望は必ず1グループにだけ入れる
- メモ: 束になっていた「AIだらけ」問題は **P2（方針）** と **T6（均等化の実装）** に分解した

## A. 質問（調べて答える。実装は任意）

| ID | 内容 | 現時点での答え・メモ | 状態 |
|----|------|----------------------|------|
| Q1 | フィード本文はどう取得してる？ AI経由なら無駄では | 本文抽出は `@mozilla/readability`（HTMLパース、**AI不使用**）。AIを使うのは「X風要約」生成だけ（Claude Haiku）。→ 本文取得自体は無駄になっていない。論点があるとすれば「要約をHaikuに通すコスト」のほう | 回答済み |
| Q2 | いいねでフィードがどれだけ変わるか直感的に知りたい | 現状 Phase1 は `prompt_score` 順のみで **いいねは並びに未反映**。学習層（いいね中心ベクトルからの類似度）は Phase2。「どれだけ変わるか」を見せる仕掛け自体が未実装 → 可視化は Phase2 の検討事項 | 要検討 |
| Q3 | Superpowers は必要か | noiseless 本体ではなく Claude Code の設定の話。プロダクトとは別軸。別途見直す | 別軸 |

## B. 方針・戦略の決定（作る前に決める）

| ID | 内容 | 論点 | 状態 |
|----|------|------|------|
| P1 | Feedly 等との差別化を確保できているか | 現状の差別化要素＝「いいね学習」「日本語訳」「有限フィード（読み切れる）」「完全1人最適化」。これで RSS リーダー／Feedly と十分に違うと言えるか。設計書 §11 と突き合わせて再評価 | 要判断 |
| P2 | コンテンツ編集方針（AI偏り） | AI に偏りすぎている。AIソースを減らすか／選んだカテゴリが**同じぐらいの分量で**出るのを理想にするか。IT専用フィードなのに多様性がない問題 | 要判断 |
| P3 | 論文（arXiv）の扱い | 高度すぎてサラッと読めない＝邪魔かも。選択肢: ①除外する ②レベル設定（LEVELS）で出し分ける ③任意オプション化 | 要判断 |
